# 运维用户手册

面向 `ops1`（运维管理员，角色 `OPERATOR`）。普通读者账号只能查看部分状态，不能做备份、恢复、切换。

## 1. 登录与入口

浏览器打开 `http://<部署地址>/`，用运维账号登录，进入“运维管理员工作台”。左侧导航：

- **主备服务器**：节点角色、数据库连接、复制状态与延迟、切换入口；
- **备份与恢复**：备份列表、创建备份、恢复到验证库、任务历史。

直接访问 `/api/ops/health` 不需要登录，用于探活；其余接口都要 `Authorization: Bearer <token>`。

## 2. 主备服务器页

> 当前云主机演示使用 `OPS_EXEC_MODE=local`：节点卡片“容器”一栏显示的是数据目录，node-a 为 `/home/user/og/data`（15432，备），node-b 为 `/home/user/og/data-b`（15443，主）。Docker 模式的节点显示容器名和 15432/15433。

页面顶部是两张节点卡片：

| 字段 | 含义 | 正常值 |
| --- | --- | --- |
| 节点 | 容器名 / 本机数据目录 | `library-opengauss-a` / `-b`，或本地 datadir |
| 角色 | 当前角色 | 一主一备 |
| 数据库状态 | `gs_ctl query` 的 `db_state` | `Normal` |
| 复制状态 | 主备复制链路 | `STREAMING` / `DEGRADED` |
| 延迟（秒） | 备库 sent/replay LSN 是否已追平 | 追平为 0；未追平显示“—”（openGauss 无秒级 replay_lag 字段） |
| 地址 | 节点 SQL 端口 | Docker 常用 15432 / 15433；本机原生双实例用 15432 / 15443 |

下方“数据库连接”显示库名、当前主节点、是否可达、采集时间。数据库不可达时整页不报 500，而是把 `reachable` 标红并显示错误原因，旧的任务记录仍可查看。

单实例部署（没有备节点）时，复制状态显示 `SINGLE`，节点只有一张卡片，这是正常现象。

## 3. 创建备份

1. 进入“备份与恢复”，点“创建备份”；
2. 备注填用途，例如 `切换前基线`；
3. 提交后页面出现任务，每 1.5 秒刷新一次步骤。

任务步骤：

| 步骤 | 做什么 | 成功标志 |
| --- | --- | --- |
| 检查主节点与数据库 | 确认当前主节点 / 数据目录可达 | `primary=...` |
| 执行 gs_dump | docker 模式在容器内、local 模式在本机执行 `gs_dump -F c` | 退出码 0、耗时 |
| 取回归档 | docker 模式 `docker cp`；local 模式直接写 `OPS_BACKUP_DIR` | 出现 `.dump` 文件 |
| 计算校验和并写清单 | SHA-256 + 大小 + 时间 + 操作人 | 同目录出现 `.dump.json` |

完成后列表新增一行：文件名、时间、大小、备注、SHA-256。备份文件默认不提交 Git。

## 4. 恢复到验证库

**禁止直接恢复到 `library`。** 页面默认目标库是 `library_verify`，只接受 `library_verify` 开头的库名；服务端还有一道开关 `OPS_ALLOW_PRODUCTION_RESTORE=false` 兜底。

操作：

1. 在备份行点“恢复到验证库”；
2. 目标库填 `library_verify_日期`，例如 `library_verify_1123`；
3. 勾选确认，提交；
4. 任务详情里看四步：校验备份 → 重建空库 → `gs_restore` → 对象核对。

对象核对 8 项（与 D 的 `tests/recovery/15-对象核对清单.sql` 对应）：

| 项 | 期望 |
| --- | --- |
| schema 数 | 4 |
| `loan` 索引数 | 2 |
| `report` 索引数 | 4 |
| 存储过程数 | 2 |
| 审计触发器数 | 1 |
| 关键表行数（`loan_record` / `catalog.book` / `iam.app_user`） | 实际值打印在任务结果里，供 D 与备份时记录对照 |

任何一项不符，任务标 `FAILED`，页面展示实际值/期望值对照；此时不要拿这个库去做验收，先看任务日志里的 `gs_restore` 输出。

恢复成功后：

- 页面任务结果里有 `objectCheck` 明细和 `sha256`；
- 用 `gsql` 连 `library_verify_*` 抽查书目、借阅记录；
- 请 D 按 `15-对象核对清单.sql` 复核，请 C 在该库上借还一本书（需要临时把 loan-service 的 JDBC 指向验证库，验证完切回）。

## 5. 主备切换

前置条件：

1. 状态页显示一主一备、`db_state=Normal`、复制 `STREAMING`；
2. 没有正在运行的备份/恢复任务（任务串行，提交会被排队或拒绝）；
3. 业务低峰，提前通知 C/D。

操作：主备服务器页 →“切换主备”→ 阅读提示 → 勾选确认 → 提交。

任务步骤：确认一主一备 → 在备节点执行 `gs_ctl switchover` → 轮询角色互换 → 新主建临时表验证可写。

成功后：

- 节点卡片角色互换，各节点端口不变；本机原生双实例的结果是 node-b 主 15443 / node-a 备 15432；
- 备份/恢复任务会自动跟随新主，不需要改配置（local 模式按数据目录映射端口）；
- 业务方使用双地址 JDBC（`targetServerType=master`）时会自动重连新主；如果是单地址，需要把 `LIBRARY_JDBC_URL` 指到新主端口并重启服务；
- 让 C 重新登录借一本书，确认写入正常。

失败处理：任务详情会给出 `gs_ctl` 输出；不要连续重试，先确认两节点角色（`gs_ctl query`），必要时按 HA README 手工恢复一主一备。

## 6. 任务记录

- 所有备份/恢复/切换都生成任务，含 `id`、类型、状态、操作人、参数、步骤、日志、结果；
- 记录存放在 `OPS_TASK_DIR`（Docker 默认容器卷 `dbops-tasks`；本机原生演示为 `/home/user/dbops-tasks`），**不在业务库**，所以业务库故障/恢复时任务历史不丢；
- 页面任务列表按时间倒序，可看历史；服务重启后历史仍在；
- 任务日志里的数据库口令会被替换为 `***`，不要把带明文口令的终端输出贴进文档。

## 7. 用命令行代替页面

`deploy/scripts/` 下：

| 脚本 | 用途 |
| --- | --- |
| `backup-demo.ps1` | 创建备份并等待完成 |
| `restore-verify.ps1` | 恢复到 `library_verify_*` 并打印对象核对 |
| `switchover-demo.ps1` | 预览切换；加 `-ConfirmSwitch` 才真正提交 |
| `demo-backup-restore.ps1` | 备份 → 改一本演示书书名 → 恢复 → 对比两库 |

示例：

```powershell
cd deploy\scripts
.\backup-demo.ps1 -OperatorPassword 123456789000 -Note "切换前基线"
.\restore-verify.ps1 -OperatorPassword 123456789000 -BackupId <dump文件名>
.\switchover-demo.ps1 -OperatorPassword 123456789000 -ConfirmSwitch
```

脚本会先调 `/auth/login` 取令牌，再调 `/api/ops/*`；失败时打印 HTTP 状态和响应体。

## 8. 错误码与处理

| HTTP | 含义 | 处理 |
| --- | --- | --- |
| 401 | 没登录/令牌过期 | 重新登录 |
| 403 | 角色不是 `OPERATOR` | 换 `ops1`；`analyst01` 只能读状态 |
| 409 | 有任务在跑，或参数不合法（备份文件名、目标库名、未确认） | 按响应 `message` 修正；等当前任务结束再提交 |
| 400 | 查询参数不合法（如 `limit` 不是数字） | 修正参数 |
| 503 | 数据库/容器不可达 | 先查容器与口令，任务会记录失败原因 |
| 502 | Nginx 连不到 dbops | 检查 `dbops-service` 是否启动、路由是否生效 |

## 9. 安全约定

- 运维页面只在内网/本机使用，不对公网开放 18085；
- 不把 `.env`、dump、任务日志原文发到群里；
- 恢复操作默认只能碰 `library_verify*`，不要为了省事打开生产覆盖开关；
- 演示结束后清理验证库，避免占满磁盘。

## 8. 数据库连接页（2026-11-24 新增）

侧栏「数据库连接」是独立页，不再和主备挤在一起。上面显示：

| 项 | 含义 |
| --- | --- |
| 数据库 | 当前连的库名，例如 `library` |
| 连接账号 | 运维采集用的库账号（`gaussdb`） |
| 会话 / 连接数 | `pg_stat_activity` 里的连接数，用来判断有没有连接泄漏 |
| 最近采集 | 这次状态是什么时候读的、耗时多少毫秒 |
| 服务角色 | 单实例，或「主备部署 · 主节点 node-a」 |
| 任务存储 | 任务 JSON 落盘目录与文件数 |
| 版本 | openGauss 完整版本串 |

右上角「刷新状态」会重新采集一次。页面只读，不提供任何写操作。

> 主备页在单实例部署下会把「主备切换」置灰并提示「未配置备节点」，这是预期行为，不是故障。
