# 两个读者的登录与数据库身份

打开 A 的 [读者登录页](http://127.0.0.1:8081/)，先用 `reader01` 登录，再在同一页面换成 `reader02`。输入的是各自的图书室账号密码。两次登录会分别查询 C 当前连接的数据库会话。

| 应用账号 | A 返回的编号与角色 | C 查询的 current_user | C 查询的 session_user |
| --- | --- | --- | --- |
| reader01 | 1，READER | db_loan_reader01 | db_loan_reader01 |
| reader02 | 2，READER | db_loan_reader02 | db_loan_reader02 |

## A 原演示电脑的快捷方式

以下快捷方式位于原电脑工程外层的 `.tools/reader-demo`。新克隆的工程请按下方「组员在自己的开发机复现」启动。

1. 在资源管理器中双击 `查看本机演示账号.cmd`，窗口会显示两个读者各自的密码。
2. 打开上方的读者登录页，用第一组账号和密码登录。看到数据库会话后，把账号换成第二组，再输入对应密码登录。
3. 如果电脑刚重启，先双击 `重新启动读者演示.cmd`，看到 `Ready` 后再打开登录页。此入口使用本机 VMware 里的课程开发库。

2026-11-19 已在本机浏览器验证表中两行结果，见 [reader01 截图](identity-evidence/reader01.png) 和 [reader02 截图](identity-evidence/reader02.png)。第二人登录后，使用第一人的原令牌再次查询，仍然返回 `db_loan_reader01`。输入错误密码会清空上一位读者的结果，接口拒绝缺失和无效的令牌。

## 请求如何经过两个服务

1. 页面向 A 发送 `POST /auth/login`，请求字段为 `username` 和 `password`。A 以 `db_iam_runtime` 查询 D 的 IAM 表，校验密码哈希后返回 `accessToken`、`tokenType` 与 `expiresIn`。
2. 页面携带令牌请求 A 的 `GET /demo/loan-identity`。A 将请求转发给 C 的固定地址 `GET /api/me`。单独调试 C 时也可直接访问此接口。
3. C 带同一令牌回查 A 的 `GET /users/me`。返回示例为 `{"id":1,"username":"reader01","roles":["READER"]}`。
4. C 按当前演示名单选定数据库连接池，执行 `SELECT current_user AS current_user, session_user AS session_user`。页面展示 C 的查询结果。

令牌有效期一小时，保存在 A 的进程内，重启 A 后重新登录。禁用、软删除或调整角色在下次身份查询时生效。读者密码存储为带随机盐的 PBKDF2-HMAC-SHA256 哈希。

## 组员在自己的开发机复现

先按 [D 的共享数据库说明](../database/opengauss/README.md) 准备开发库，已有种子和授权时可以直接使用。这个身份查询只读会话用户名，不依赖 C 的借还过程。若使用统一的开发库角色密码，在本机 `database/opengauss/.env` 的 `LIBRARY_LOCAL_PASSWORD` 中填入该密码。读者在登录页输入的是自己的应用密码。

在 `campus-library` 工程根目录打开两个 PowerShell 窗口。第一次启动 A 时为两个种子读者各设一个 12～256 字符的应用密码。脚本支持 `-Maven` 与 `-JdkHome` 参数，已有可执行 JAR 时可直接用 Java 21 启动。

```powershell
# 窗口 1，A
.\start-identity.ps1 -InitReaders
# 以后启动 A 只需 .\start-identity.ps1
```

```powershell
# 窗口 2，C；已打包过 C 时可加 -UseJar
.\start-local.ps1
```

第一次构建两个服务需要 Maven 和 JDK 21。真实联调时，8081 由 A 使用。C 的 `tests/loan/identity_stub.py` 仅供独立测试时使用。

连接组内其他机器的数据库时，在 A 的窗口设置 `IAM_DB_URL`，在 C 的窗口设置 `LOAN_DB_URL`。两者均为完整的 JDBC 地址，本机默认值为 `jdbc:opengauss://localhost:15432/library`。如果数据库为每个角色设置了独立口令，在 A 的窗口设置环境变量 `IAM_DB_PASSWORD`，在 C 的窗口设置 `LOAN_DB_READER01_PASSWORD`、`LOAN_DB_READER02_PASSWORD` 和 `LOAN_DB_LIBRARIAN01_PASSWORD`。这些显式变量优先于统一口令。两个脚本也支持 `-EnvFile` 指向包含 `LIBRARY_LOCAL_PASSWORD` 的私有文件。容器间互访详见 [部署说明](../deploy/local-identity/README.md)。

`-InitReaders` 只设置 D 的 `REPLACE_WITH_HASH` 种子占位值。已有账号继续用原密码。如果两个种子属于别人的共享开发库，先确认用于该库的演示密码。

## 验证两次登录

从工程根目录运行以下命令并按提示输入两个读者密码。脚本分别检查 A 的账号与角色、C 的两个数据库身份，以及页面实际使用的转发路径。它还会用第一位读者的令牌再查询一次，并检查缺失、无效令牌是否被拒绝。输出不包含密码和令牌。

```powershell
python tests/identity/reader_flow.py
```

如果 A 可以登录但页面取不到数据库会话，分别检查 C 的 8083 端口、C 的数据库地址和每个借阅账户的密码。C 的 `/api/health` 显示 UP 只能证明进程已启动。
