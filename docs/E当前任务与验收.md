**先从正在运行的演示库做一份新备份，恢复到另一个空库，请 D 核对，再请 C 在恢复出的库里借还一本书。** 这一步做通后，再搭主备、接网页按钮。今天就能从本地开始。

日期为 2026-11-23。A、B、C、D 的共享代码基线为 [团队仓库 `a40f193`](https://github.com/bit-campus-library-team/bit-campus-library/tree/a40f193)。以下路径都从仓库根目录算起。

## 先跑通 Docker 和备份恢复

1. **跑通容器。** 准备 E 自己的演示库，让应用容器能连到它。在 `deploy/local-identity` 将 `.env.example` 复制为本机的 `.env`，填写实际数据库地址和各角色密码。已有数据库账号的环境可在该目录运行下面两条命令。新建环境的账号初始化步骤见[容器部署说明](../deploy/local-identity/README.md)。

   ```powershell
   docker compose -f compose.yaml -f compose.web.yaml up -d --build
   docker compose -f compose.yaml -f compose.web.yaml ps
   ```

   打开 `http://127.0.0.1:8080/`，用读者账号登录并查一本书。留一张容器状态图和一张页面操作图。

2. **做一次新备份。** 在这套完整演示库里选一本测试书，记下 ISBN 和原书名。用 `gs_dump -F c` 导出当前数据库，记下备份文件和时间。然后只在演示库里修改这本书的书名。请 B 指出封面目录，另存封面文件；请 D 提供数据库角色及授权脚本。
3. **证明能恢复。** 新建独立验证库，用 `gs_restore` 恢复刚才导出的归档。按同一 ISBN 查询，验证库应显示**原书名**，原演示库应显示**修改后的书名**。请 D 跑[恢复对象核对清单](../tests/recovery/15-对象核对清单.sql)，核对关键表行数、索引、借还过程、审计触发器与权限。让一套测试用的书屋连接验证库，请 C 实际借还一本书。把两个库的查询结果、核对结果和借阅编号发给 A。

## 接下来三项工作

| 顺序 | E 要做什么 | 验收时给大家看什么 |
| --- | --- | --- |
| 1. 搭主备，做一次切换 | 建立两个有复制关系的 openGauss 节点，让书屋能在切换后连到新主库。先确认复制正常，再做一次计划内主备切换。 | **切换前后各一张节点状态图，加一笔新的借阅记录。** 图里能分辨哪台是主、哪台是备；切换后请 C 在网页借一本书，记下编号和恢复可写的耗时。 |
| 2. 把运维接进网页 | E 开发 `dbops-service`。和 A 约定网页请求的地址，和 B 接好状态、备份、恢复、切换页面。点击后返回任务编号，页面显示进度、成功或失败原因。任务记录存在业务库之外。执行程序只接收约定好的操作，恢复或切换前在页面显示目标并确认。 | `ops1` 能查看主备状态、发起备份并看到结果；`reader01` 发起相同请求时返回 `403`（没有权限）。服务停机时，页面能显示异常，之前的任务记录仍能查看。 |
| 3. 上云并交付环境 | 把实测通过的镜像部署到云平台，按课程推荐可用华为云。记录镜像版本、部署命令、网络配置和访问方式，再整理 VMware 演示环境。 | 一位组员从另一台电脑打开云端书屋并完成登录、查书和借阅；另一位组员能按说明启动交付的 VMware 环境。 |

## 找谁配合，最后交什么

- **找 A** 领运维账号，定接口地址和权限。建议网页统一从 `/api/ops/` 访问 E 的服务。A 在 `deploy/dev-server.py` 和 `deploy/nginx.conf` 都加上转发规则，本地代理要先匹配 `/api/ops/` 再匹配 `/api/`。A 收集 Docker 和云端实测截图做汇报。
- **找 B、C、D** 分别确认运维页面与封面目录、切换后的借还结果、恢复后的数据库对象。各自提供对应的截图或记录，E 汇总测试报告和用户手册。
- **体系结构课** 交 Docker 部署说明、云部署说明和可启动的 VMware 环境。E 汇总 15 分钟录屏的素材，负责演示镜像构建发布、部署和运维。
- **高斯数据库课** 准备好可恢复的演示数据和完整日志，在 10 分钟小组演示中负责“备份 → 恢复 → 核对”和“主备切换 → 新借阅”。最终与全组源码、文档和用户手册一起打包。
