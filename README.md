# BIT 书屋 · 校园图书借阅系统

BIT 书屋把找书、借还、馆藏管理和借阅统计放在同一个网页里。读者用自己的账号借书，馆员、数据分析员和运维员登录后，从右上角的 **管理控制台** 进入各自的工作页面。

**云端现状（2026 年 11 月 24 日晚）**：书屋首页、书目列表与按书名搜索都已正常。当天早些时候列表返回 `503`，原因是云库缺少馆藏扩展、书评公告和检索函数三份补丁（`010_web_schema.sql`、`003_reviews_announcements.sql`、`020_book_search.sql`），现已按顺序补齐。云服务器上运行着网页、身份、馆藏、借阅、报表、运维六个应用容器，以及一个 openGauss 数据库容器；馆藏 11 本、14 册，其中 7 本带电子书（PDF/EPUB）；读者自助注册已上线，注册后可以直接借还——新读者在库里没有单独角色，走的是共享的最小权限角色（见下节）。馆内新增《Computer Systems: A Programmer's Perspective》与《高等营养全书》。

## 读者怎样借还一本书

以下是馆藏查询正常时的使用方法。已有小组演示地址的同学，用浏览器打开书屋即可。

1. 点 **全部图书**，输入书名或作者，选择一本还有可借副本的书。卡片上会写明可借几册；显示“已借完”表示这本书的副本都借出去了。
2. 点右上角 **登录**，输入读者账号和书屋密码。点自己的用户名，可查看本次使用的借阅数据库身份。用 `reader01` 登录应看到 `db_loan_reader01`，用 `reader02` 应看到 `db_loan_reader02`；自助注册的读者看到的是共享角色 `db_loan_selfreader`，具体是谁由事务里的 `reader_id` 决定。
3. 选中图书，点 **确认借阅**。打开 **我的借阅**，核对书名、借出日期和应还日期。
4. 要归还时，在 **我的借阅** 找到同一条记录，点 **归还 → 确认归还**。要验证个人记录隔离，可在用户名菜单中选择 **切换账号**，再查看另一位读者的借阅记录。[读者身份实测记录](docs/读者登录联调.md)

## 注册读者账号

网页右上角「注册」和登录弹窗底部的「注册一个」都能进入注册表单。用户名 3–32 位、字母开头、可含数字和下划线；密码至少 8 位。注册成功自动登录，账号只拿到 `READER` 角色。

注册接口是 `POST /auth/register`，由身份服务处理。密码与演示账号使用同一套 PBKDF2-SHA256（60 万轮）哈希；用户 id 按 D 的约定在应用层分配，并用表锁串行化，避免并发注册撞号。同一来源每分钟最多 12 次——放到 5 次时，教室同一个出口几个人一起注册会互相挤。

注册时填的显示名会出现在页头，账号名仍用于登录。注册成功后自动登录并回到首页。

### 自助注册读者的数据库身份

演示账号一人一个库角色（`db_loan_reader01`、`db_loan_reader02`、`db_loan_librarian01`），注册用户人数不固定，不可能一人建一个角色，也不该为此改动按角色授权的模型。所以：

- 借阅服务用一个共享的最小权限角色 `db_loan_selfreader` 连接数据库，只有 `loan` 的查询权限和两个借还过程的执行权，没有建表、改授权的能力；
- 具体是谁由借阅服务在事务内声明（`library.reader_id`），`loan.actor_id()` 只对这个共享角色读取该变量，其他角色读不到也用不上；
- 首次进入借阅时，`loan.fn_ensure_borrower()` 补一行借阅人档案，否则存储过程会报 `READER_NOT_FOUND`；
- 审计表里记录的仍是真实用户 id：自助读者借还各写一条，`operator_user_id` 就是本人，不是共享角色。

落库脚本见[自助读者库角色](database/patch/2026-11-24_self_registered_readers.sql)。

## 电子书下载

详情页有一张「电子书下载」卡片：后端有文件就显示文件名、大小和「下载 PDF / EPUB」，没有就写明「后端暂无电子书」。下载不需要登录，浏览器直接保存。

文件本身不存库，落在宿主机 `/opt/library-files`，库里只记元数据：

| 表 | 存什么 |
| --- | --- |
| `catalog.ebook` | `book_id`、文件名、字节数、上传人、更新时间；一本书一份，重新上传即覆盖 |

馆员在 **控制台 → 图书管理 → 编辑图书** 里上传，支持 PDF 与 EPUB，按文件头校验（`%PDF-` / ZIP），单文件上限 300 MB。当前 7 本带电子书：CSAPP、Advanced Nutrition，以及新导入的 5 本营养与运动科学参考书（其中两本食物成分表是 EPUB）。

上传要过两道闸门：Nginx `client_max_body_size`（现为 320 MB）和容器内 multipart（300 MB），两者任何一处偏小都会让大文件在网关或容器层被拒。

## 项目是怎样运行的

网页通过统一入口把请求交给五个独立后端。以借书为例，身份服务先确认读者身份，借阅服务再用对应的数据库身份调用借书过程（演示账号一人一个库角色，自助注册读者用共享角色并在事务内声明操作人），在同一事务中登记借阅并修改副本状态。触发器留下审计记录；报表服务随后读取借阅变化并更新统计。

| 组件 | 负责的事情 |
| --- | --- |
| [网页](web/)与[网关](deploy/nginx.conf) | 提供读者页和管理控制台，把同一个网站下的请求转给相应服务。 |
| [身份服务](services/identity-service/) | 验证账号密码、签发登录令牌、返回用户及角色。 |
| [馆藏服务](services/catalog-service/) | 查书、维护书目、管理评价和公告，处理书目 CSV 导入导出。 |
| [借阅服务](services/loan-service/) | 选择读者数据库连接，处理借出、归还和个人记录。 |
| [报表服务](services/report-service/) | 同步借阅变化，按条件查询、统计和导出数据。 |
| [数据库运维服务](services/dbops-service/) | 检查操作权限，执行备份、恢复及计划内切换，记录任务结果。 |

四个业务服务使用 Java，运维服务使用 Python。openGauss 中的身份、馆藏、借阅、报表分别使用不同的 schema 和角色授权。库内共 10 个业务登录角色：9 个按人分配（身份 1 个、馆藏 3 个、借阅 3 个、报表 2 个），外加 1 个自助注册读者共用的 `db_loan_selfreader`。[数据库设计与初始化说明](database/opengauss/README.md)

## 在自己的电脑上运行

1. 准备 Java 21、Maven、Python 3，以及可访问的 openGauss `library` 库。首次建库按[数据库说明](database/opengauss/README.md)准备用户和基础数据。完整网页还需要按顺序安装[馆藏扩展](database/catalog/010_web_schema.sql)、[书评与公告](database/patch/003_reviews_announcements.sql)和[书目检索函数](database/catalog/020_book_search.sql)。要用自助注册，再执行[自助读者库角色](database/patch/2026-11-24_self_registered_readers.sql)；用 SQL 直接灌过书目的库，补一次[借阅快照](database/patch/2026-11-24_backfill_loan_snapshots.sql)。已有数据的库先核对对象，整库恢复只用于空库。
2. 将 [env.example](database/opengauss/env.example) 复制成同目录的 `.env`，填写自己开发库的连接与业务角色口令。容器部署另用 `deploy/local-identity/.env`，其中除三个 `LOAN_DB_*_PASSWORD` 外还要填 `LOAN_DB_SELFREADER_PASSWORD`，值必须与建角色时一致。新库首次启用演示账号时，另行设置各自的 `IAM_SEED_…_PASSWORD` 网页密码，长度为 12～256 个字符。已有账号沿用原密码。
3. 在工程根目录执行下面的命令。看到 `Ready` 后打开 [本机书屋](http://127.0.0.1:8080/)，用完在启动窗口按 **Ctrl+C**。下次也可以双击 [启动书屋.cmd](启动书屋.cmd)。

```sh
python scripts/run_library.py --build
```

仓库当前的本地启动器启动四个 Java 业务服务和网页代理。运维后端需另行启动并连接实际数据库工具。组内云端采用 Docker 部署；容器配置和业务入口见[应用编排目录](deploy/local-identity/)。

## 部署时容易踩的几处

- **重建服务后重启网关**：Nginx 在启动时解析上游容器名，`identity-service`、`loan-service` 重建后 IP 会变，网关不重启就会一直 `502`。改完代码执行 `up -d --no-build <服务>` 之后，再 `restart web`。
- **`.env` 的变量名不能改**：compose 按名字插值，名字被改写成别的样子（哪怕是"加密"）会直接启动失败，报 `Set ... in .env`。变量清单以 `deploy/local-identity/.env.example` 为准。
- **上传大小要同时改两处**：Nginx 的 `client_max_body_size` 和 `spring.servlet.multipart.max-file-size`；只改一处，大文件仍会在另一层被拒，表现为「上传没反应」。
- **ISBN 允许为空**：openGauss 的 A 兼容模式把空串当 NULL，所以 `catalog.book.isbn` 与 `loan.book_snapshot.isbn` 已改为可空；用 SQL 灌书目时写 `NULL`，不要写 `''`。
- **用 SQL 灌书目要补快照**：`loan.book_snapshot` 是借阅侧对书目的只读副本，走服务层导入时会自动写；直接用 SQL 插 `catalog.book` 会漏掉，借书时返回 `409 BOOK_SNAPSHOT_MISSING`。
