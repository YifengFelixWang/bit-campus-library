# 校园书屋数据库设计说明书

## 概述

本库为课程「校园书屋」的单一 openGauss 实例、单库 `library`，按业务拆成四个 schema：`iam`、`catalog`、`loan`、`report`。表结构由 D 定稿维护；各服务以各自数据库用户只访问本 schema。跨 schema 仅保存对方编号，不建数据库外键。时间约定为 `Asia/Shanghai` 墙钟，`TIMESTAMP`；接口序列化格式为 `yyyy-MM-dd'T'HH:mm:ss.SSSSSS`，不带 `Z`。

环境与镜像锁定见 [00-环境记录.md](00-环境记录.md)。边界与命名见 [01-边界与命名.md](01-边界与命名.md)。

## 关系模式

| Schema | 主要表 | 写入方 |
| --- | --- | --- |
| iam | `app_user`、`app_role`、`user_role`、`db_identity_mapping` | A 身份服务 |
| catalog | `category`、`book`、`author`、`book_author`、`media` | B 书目服务 |
| loan | `borrower_account`、`book_copy`、`book_snapshot`、`loan_record`、`request_dedup`、`loan_audit` | C 借阅服务 |
| report | `category_dim`、`book_dim`、`reader_dim`、`loan_fact`、`sync_checkpoint` | D 报表服务 |

`report` 投影表之间不建外键；`loan.book_snapshot` 与 `report.book_dim` 职责分离，互不更新。

## 约束与索引

- 外键仅在同一 schema 内建立（如 `loan.loan_record` 引用 `loan.book_copy`、`loan.borrower_account` 等）。
- 状态枚举：`loan` 借阅单 `BORROWED`/`RETURNED`，副本 `AVAILABLE`/`BORROWED`；`iam.app_role.role_code` 为 `READER`/`LIBRARIAN`/`ANALYST`/`OPERATOR`。
- 业务索引（源脚本 `loan/001_schema.sql`、`report/001_schema.sql`）：
  - `loan.loan_record`：`idx_loan_user_status (user_id, status)`
  - `loan.book_copy`：`idx_copy_book (book_id)`
  - `report.book_dim`：`idx_book_dim_category (category_id)`
  - `report.loan_fact`：`idx_loan_fact_time_status (borrowed_at, status)`、`idx_loan_fact_book (book_id)`、`idx_loan_fact_user (user_id)`

集群登录用户模板见 `roles/001_users.sql` 与 `dist/001_roles.sql`；表级授权见 `roles/002_grants.sql`。应用账号与数据库用户映射见 [03-账号对照.md](03-账号对照.md)。

## 存储过程与触发器

正文在仓库 `database/loan/002_procedures.sql`，不在本目录重复粘贴。对外签名以 [docs/D联调交接.md](../../docs/D联调交接.md) 为准：

- `loan.sp_borrow_copy(BIGINT, BIGINT, INTEGER, VARCHAR, BIGINT)`
- `loan.sp_return_copy(BIGINT, VARCHAR)`

过程 EXECUTE 授权在 `database/loan/004_execute_grants.sql`（五参数版本）。`roles/003_execute_grants.sql` 仅保留说明，旧四参数示例已作废。

**过程复核（R7）：**

1. 借阅上限、副本可用性、幂等与期限核对等业务规则在 `sp_borrow_copy` / `sp_return_copy` 过程体内实现。
2. 触发器 `loan_audit_trigger` 调用 `loan.audit_change()`，仅向 `loan.loan_audit` 插入审计行。
3. 过程不提交事务；异常时由调用方（C 服务）开启的事务整体回滚。
4. 过程与触发器只读写 `loan` schema 内对象，不写 `catalog` 或 `report`。

## 投影与同步

`report` 五张表由 D 的 report-service 维护。当前实现**仅**从 C 的借阅变更内部接口拉取 `loan_record` 投影到 `loan_fact`，并维护 `sync_checkpoint` 中 `source_name='loan'` 的游标。

身份（`reader_dim`）与书目（`category_dim`、`book_dim`）的同步接口尚未提供；控制台借阅统计页对 iam、catalog 来源显示「接口未提供」。同步身份为应用层 sync-bot，数据库写入用户使用 `db_report_sync`。

## 备份对象核对

备份与恢复操作由 **E** 在部署环境执行。本节仅列出 D 交付物中应被逻辑备份覆盖、并在恢复后可用 [tests/recovery/15-对象核对清单.sql](../../tests/recovery/15-对象核对清单.sql) 抽查的对象：

- 四个 schema 及全部 D 定稿表、约束、索引、演示种子与 `roles/002_grants.sql` 中的表权限。
- C 扩展：`loan.sp_borrow_copy`、`loan.sp_return_copy`、`loan_audit_trigger` 及 `004_execute_grants.sql` 中的 EXECUTE 授权（已编入当前 `dist/library.sql` 导出流程）。
- 不包含：B 书屋扩展的 `reviews`/`announcements`、书目检索函数 `fn_search_books`、封面二进制文件（由 B 清单维护）。
- 不包含：主备复制关系（E 另行配置）。
