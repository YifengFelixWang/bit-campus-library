# 导入顺序和重新生成顺序

## 全组导入

开发机和 E 的部署都按这段做。

1. 安装 Docker Desktop，拉取环境记录里的 openGauss 7.0 镜像，平台使用 linux/amd64。
2. 启动容器，把容器内的 5432 映射到主机 15432，创建数据库 `library`。初始化账户只用于下面两步导入。
3. 按 [共享版初始化说明](README.md) 运行 `init_roles.py`，它在维护库 `postgres` 内处理 `dist/001_roles.sql`，创建集群登录用户。
4. 执行 `database/opengauss/dist/library.sql`。里面是四个 schema、表、约束、授权和演示数据。
5. 各服务按本机的 `.env` 连接自己的业务用户。主机 `localhost`，端口 `15432`，库名 `library`。不使用初始化账户。

逻辑备份不包含主备复制关系，E 在两台数据库节点上另行配置。逻辑备份不包含封面图片，封面清单由 B 维护。云主机导入后，E 替换初始化账户和业务账户的口令，云口令不写回仓库。

## 只有 D 重新生成 dist

1. 用同一镜像启动一个空的 `library`。
2. 在维护库按 [初始化说明](README.md) 创建角色，或使用已准备的角色。随后在空的 `library` 内依次执行四套 `001_schema.sql`、`roles/002_grants.sql`、`seed/001_demo.sql`。
3. 用初始化账户执行 `gs_dump -F p`，输出覆盖 `database/opengauss/dist/library.sql`。
4. 把 `roles/001_users.sql` 复制为 `database/opengauss/dist/001_roles.sql`。
5. 如需在新快照中一并交付 C 的过程，先执行 `../loan/002_procedures.sql` 和 `../loan/004_execute_grants.sql`，再导出并记录已包含的内容。

`dist/001_roles.sql` 与 `dist/library.sql` 已生成，可按第一段顺序导入。
