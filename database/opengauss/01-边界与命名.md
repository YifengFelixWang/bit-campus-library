# 边界与命名

1. 一个 openGauss 实例、一个数据库 `library`、四个 schema：`iam`、`catalog`、`loan`、`report`。schema 是同一个库里的逻辑分区，不是四台数据库。
2. 建表脚本全部由 D 维护。运行时的写入方是：
   - `iam`：`app_user`、`app_role`、`user_role`、`db_identity_mapping`。由 A 的服务写入。
   - `catalog`：`category`、`book`、`author`、`book_author`、`media`。由 B 的服务写入。
   - `loan`：`book_copy`、`borrower_account`、`loan_record`、`request_dedup`、`loan_audit`、`book_snapshot`。由 C 的服务写入。过程和触发器也由 C 创建。
   - `report`：`reader_dim`、`book_dim`、`category_dim`、`loan_fact`、`sync_checkpoint`。由 D 的服务写入。
3. 真实外键只建在同一个 schema 内部。跨 schema 只保存对方的编号，不建数据库外键。
4. report 里的投影表之间也不建外键。同步时分类、图书、借阅可能不在同一页到达。对应关系靠相同的编号维持。
5. 每个服务的运行账户只访问本 schema。
6. 编号类型都用 `BIGINT`，由写入方的服务生成。唯一例外是 `loan_audit.audit_id`，由数据库生成。
   - `user_id`：A 生成。C 的 `borrower_account.user_id` 使用同一个值。
   - `category_id`、`book_id`、`author_id`：B 生成。
   - `copy_id`、`loan_id`：C 生成。
7. `book_snapshot` 只给借还页面显示书名，由 C 写入。`book_dim` 只给统计查询，由 D 从 B 的接口同步。两张表不互相更新。
8. 读者显示名以 `iam.app_user` 为准。借阅事实以 `loan.loan_record` 为准。
9. 源表用 `updated_at` 和 `deleted` 支持同步。删除时把 `deleted` 设为真，并更新 `updated_at`。
10. 角色名称只用四个：读者、馆员、数据分析员、运维管理员。代码取值是 `READER`、`LIBRARIAN`、`ANALYST`、`OPERATOR`。数据分析员使用查询和导出，不使用导入。
11. 借阅单状态只用 `BORROWED`、`RETURNED`。实体副本状态只用 `AVAILABLE`、`BORROWED`。
12. 时间在库里用 `TIMESTAMP`。接口上的时间格式由 A 在契约里规定一种，全组遵守。
13. 首版不建 `sp_reader_summary`，不做自然语言查询。

演示编号 1 到 4 的用户、1 到 2 的分类、1 到 4 的图书、1 到 4 的副本、1 到 6 的借阅已经用于种子。新数据从这些编号之后继续分配。
