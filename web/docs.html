3.2 业务流程

借阅流程：读者登录（MD5 校验）→ 检索图书（books ⋈ categories）→ 选择图书 → 前端组装参数化请求 → 调用 sp_borrow_book → 触发器校验借阅上限、重复借阅与库存 → 写入 borrows → 触发器扣减 available 并写审计 → 事务提交后 WAL 复制到备节点。

登录→检索→借阅申请→触发器校验→写入借阅记录→库存 -1→主备同步→审计

归还流程：读者在“我的借阅”点击归还 → 调用 sp_return_book → 校验记录状态 → 更新 status='returned' 与 returned_at → 触发器恢复库存（不超过 total）→ 写审计 → 前端刷新列表与统计。借阅状态机为：borrowing → returned；到期未还时由 sp_overdue_check 置为 overdue，归还后仍进入 returned。

业务规则尽量下沉到数据库：借阅上限、重复借阅、库存不能为负、到期日必须晚于借出日等约束在存储过程与触发器中实现，应用层只做提示与界面联动，避免多个入口写入时出现不一致。

3.3 数据库编程为功能设计提供的帮助

数据库编程不是“把 SQL 写长”，而是把跨请求、跨入口的一致性规则封装到数据库侧，使应用功能更简单、更可靠，并让高可用与多用户能力有落地基础。

3.3.1 GaussDB 触发器、存储过程与“重组”

触发器的作用：借阅写入后自动扣减库存；归还更新后自动恢复库存；写入前后校验借阅上限、重复借阅与日期合法性；所有关键动作写入审计表。触发器与业务写入处于同一事务，任何一个失败都会回滚，避免“借阅记录写了但库存没扣”的半成功状态。

对象触发时机职责
fn_after_borrow / trg_after_borrowAFTER INSERT ON borrows库存 -1；库存不足时抛异常回滚；写审计
fn_after_return / trg_after_returnAFTER UPDATE ON borrows状态变为 returned 时库存 +1（LEAST(total, available+1)）；写审计
fn_validate_borrow / trg_validate_borrowBEFORE INSERT ON borrows校验 due_at > borrowed_at、借阅上限 5 本；异常回滚

“重组”与运维：课程要求中提到的“重组”可理解为数据库物理层的空间整理与在线维护。GaussDB/openGauss 提供 VACUUM、VACUUM FULL、REINDEX、表分区与在线扩容等能力：借阅日志按月份分区，历史数据可归档；频繁更新的 books.available 会产生死元组，定期 VACUUM 回收空间；索引用 REINDEX 重建以保持查询性能。触发器/存储过程保证逻辑一致性，重组保证物理性能，两者共同支撑“借阅高峰仍可稳定查询库存”的功能目标。

触发器不是越多越好：复杂业务编排仍应放在存储过程或应用服务中；触发器只承担与数据一致性强相关、必须同事务执行的规则，并避免递归触发。

3.3.2 存储过程与函数

过程 / 函数参数功能
sp_borrow_bookp_user_id, p_book_id校验读者与库存，写入借阅记录；库存由触发器维护
sp_return_bookp_borrow_id更新归还状态；触发器恢复库存并写审计
sp_overdue_check无扫描到期未还记录，批量置为 overdue
sp_hot_booksp_limit按近 30 天借阅与历史热度返回排行
sp_user_summaryp_user_id统计累计、在借与逾期数量

存储过程的价值在于：减少网络往返（一次调用完成多条 SQL）、复用业务规则（前端、后台任务、导入脚本都调用同一过程）、权限收敛（应用账户只被授予 EXECUTE，不直接授予所有表的写权限）、可审计（过程内统一写入日志）。

CREATE OR REPLACE PROCEDURE sp_borrow_book(p_user_id UUID, p_book_id TEXT)
LANGUAGE plpgsql AS $$
DECLARE v_active INT; v_stock INT;
BEGIN
  SELECT COUNT(*) INTO v_active FROM borrows
   WHERE user_id = p_user_id AND status <> 'returned';
  IF v_active >= 5 THEN
    RAISE EXCEPTION '每位读者最多同时借阅 5 本';
  END IF;
  SELECT available INTO v_stock FROM books
   WHERE book_id = p_book_id FOR UPDATE;
  IF v_stock <= 0 THEN
    RAISE EXCEPTION '库存不足';
  END IF;
  INSERT INTO borrows(borrow_id, user_id, book_id, borrowed_at, due_at, status)
  VALUES (gen_random_uuid(), p_user_id, p_book_id, NOW(), NOW() + INTERVAL '30 days', 'borrowing');
END; $$;

3.3.3 主备服务器实现

GaussDB/openGauss 主备集群通过 WAL 流复制把主节点的日志持续发送到备节点，备节点回放后保持数据一致。生产部署通常包含：

  • 复制模式：同步复制（synchronous_standby_names）保证主备强一致，或异步复制换取更低延迟；课程演示展示复制延迟与状态。
  • 仲裁与选主：由 DCS/etcd 等组件检测心跳，超过阈值判定主节点故障，按优先级提升备节点，避免脑裂。
  • 连接路由：应用连接串同时配置两个节点（host1,host2），配合 target_session_attrs=read-write 或虚拟 IP，把读写请求自动路由到新主节点。
  • 前端职责：展示主备拓扑、心跳、延迟、CPU/内存与事件日志；提供手动切换、模拟关闭主节点、恢复节点按钮；故障转移过程中提示“检测心跳 → 仲裁选主 → 提升备节点 → 更新连接 → 自动重连”。
# openGauss 主备关键参数（示例）
synchronous_standby_names = 'ANY 1 (node_b)'
wal_level = logical
max_wal_senders = 8
hot_standby = on

# 故障转移（由集群管理工具执行，应用无感）
gs_ctl failover -D /data/gaussdb/node_b
gs_ctl build -D /data/gaussdb/node_a

与功能设计的结合：借阅/归还事务提交后必须确认已同步到备节点（或允许少量延迟但明确 RPO）；故障转移后，前端仍然通过连接串访问“当前主节点”，无需改代码；运营概览中的服务器状态来自集群心跳接口，帮助管理员判断是否可以安全演练。

3.3.4 应用系统多用户设计与数据库多用户

系统把“人”和“数据库账户”分开：应用用户是 admin、librarian、reader 等业务身份；数据库账户是 gauss_dba、tata_app、tata_readonly、tata_backup、tata_audit 等连接身份，由 IAM 统一管理，浏览器永远拿不到数据库密码。

应用层 RBAC

角色 → 权限集合 → 页面/按钮/接口。前端隐藏无权限入口，后端接口再次校验；超级管理员可启停账号、重置密码、调整角色并编辑全部用户，图书管理员只能编辑本人与读者资料且账号不可修改，两类角色均可批量注册新账号，并保证至少保留一名启用管理员。

数据库层最小权限

tata_app 仅拥有业务表的 SELECT/INSERT/UPDATE 与过程 EXECUTE；audit_logs 禁止应用删除；备份账户只用于备份任务；报表账户只读；DBA 通过 IAM 登录并双因子认证。

应用角色典型权限数据库访问方式
admin全部业务 + 用户/备份/主备/审计通过后端管理接口，后端使用 tata_app；运维动作由 tata_backup / IAM 执行
librarian图书、借阅、查询、评价/公告、本人与读者资料维护、批量注册读者tata_app + 只读报表视图
reader本人借阅/归还、浏览仅通过 API 调用 sp_borrow_book / sp_return_book

密码：课程要求使用 MD5，系统在登录时计算 MD5(输入密码) 与 users.password_md5 比对，数据库中不保存明文。MD5 已不适合生产环境（无盐、易碰撞、易彩虹表），改进方向是 bcrypt/Argon2 + 随机盐 + HTTPS，并在文档与界面中明确标注。

防注入：多表联查的参数（分类、状态、关键词、阈值）通过命名参数绑定，前端只展示 SQL 模板，不把用户输入拼进 SQL 文本；后端使用 PreparedStatement 或 EXECUTE ... USING。

3.4 前端关键实现

Vue 3 单页应用

前端已重构为 Vue 3 组合式 API 单页应用，使用 hash 路由组织首页、馆内公告、全部图书、我的书库与管理控制台；公共页面、登录注册、图书详情、借阅归还与评价弹窗均由 Vue 组件管理。演示数据层保留在 db.js，通过 src/services/api.js 统一封装，后续可替换为 Spring Boot + openGauss 微服务接口，而不改动页面组件。

多表联查与 SQL 组装

数据库实验台提供四种场景：热门排行（books ⋈ categories ⟕ borrows）、借阅明细（users ⋈ borrows ⋈ books）、读者汇总（users ⟕ borrows + 聚合）、库存预警（books ⋈ categories + 过滤）。用户选择参数后，前端生成带命名参数的 SQL 并展示参数值，执行后渲染结果网格与模拟执行计划。

SELECT b.book_id, b.title, c.name AS category,
       b.borrow_count, COUNT(br.borrow_id) AS recent_count,
       ROUND(b.rating * 2, 1) AS rating_10, b.available || ' / ' || b.total AS stock
FROM books b
JOIN categories c ON c.name = b.category
LEFT JOIN borrows br ON br.book_id = b.book_id
     AND br.borrowed_at >= CURRENT_DATE - INTERVAL '30 days'
WHERE (:category = '全部' OR c.name = :category)
GROUP BY b.book_id, b.title, c.name, b.borrow_count, b.rating, b.available, b.total
ORDER BY recent_count DESC, b.borrow_count DESC
LIMIT :limit;

读者评价与十分制评分

评价表记录读者、图书、1–5 星评分、可选文字、状态与时间。提交前校验：必须已登录读者账号，且该读者存在该书的已归还借阅记录；评分必填，文字最多 500 字且可留空。图书得分由所有可见评价的平均星级折算：评分 = AVG(star) × 2，保留一位小数，即十分制。删除或隐藏评价后立即重新计算平均分与评价人数。管理端可查看全部评价（含隐藏），并可编辑星级与文字、隐藏或删除评价，保存后立即重算图书得分。

SELECT ROUND(AVG(rating) * 2, 1) AS score_10,
       COUNT(*) AS rating_count
FROM reviews
WHERE book_id = :book_id AND type = 'review' AND status = 'visible';

馆内公告

公告表保存标题、正文、置顶标记、发布状态与作者。超级管理员和图书管理员可在控制台新增、编辑、置顶、删除公告；发布状态分为“已发布”和“草稿”，访客与读者只能查询 status = 'published' 的记录。首页「馆内公告」仅展示最近 3 条，完整列表在独立公告页中查看；置顶公告优先展示。

数据导入导出

导出使用 Blob + URL.createObjectURL 生成下载文件，CSV 带 BOM 以兼容 Excel；导入使用 FileReader 读取用户选择的文件，识别表头（书名/账号）后预览前 5 行，再合并到图书或用户表。密码列导出的是 MD5 摘要；用户 CSV 导入时若提供明文密码，前端先转 MD5 再写入。所有操作在浏览器本地完成，不经过上传接口。

备份恢复：按钮在应用，执行在服务器

“备份与恢复”页面上的按钮是应用层入口，真实系统由后端执行服务器端备份：gs_dump -Fc tata_books 或 pg_basebackup，文件写入数据库服务器备份目录，返回备份编号、大小与状态；恢复时后端先校验备份，再停止写入、恢复并重启连接池。前端只负责发起、展示和二次确认。本地 JSON 下载/上传是另一条链路，适合留档与换机演示，不能替代服务器物理备份。

4.2 开发遇到的问题与解决方案

问题原因解决方案
预览页面一直显示旧版本预览层/浏览器缓存了旧 HTML 文档，服务端已更新但条件请求返回 304响应改为 Cache-Control: no-store，移除 ETag/Last-Modified，给静态资源加版本号，并在交付说明中要求强制刷新
子路径预览白屏资源使用根绝对路径（/src/main.js），在 /ports/30001 子路径下 404全部资源改为 ./ 相对路径；静态托管统一从项目根目录提供
借阅高峰库存超卖先查库存再写入，两个事务并发时都看到“有库存”存储过程内 SELECT ... FOR UPDATE 行锁 + 触发器库存非负约束；把校验与写入放在同一事务
归还后库存超过馆藏重复归还或并发归还导致多次 +1过程先校验 status <> 'returned'，触发器用 LEAST(total, available + 1) 兜底
本地存储容量不足Base64 图片与全量快照体积较大，localStorage 配额约 5 MB限制单图 512 KB、备份最多 4 份；图片只在需要时生成；异常时提示并保留内存态
ObjectURL 内存泄漏每次渲染都创建新的 Blob URL 且未释放按图书 ID 缓存 URL；替换封面时先 revokeObjectURL；页面卸载时统一释放
主备切换后前端仍连旧节点连接串只配置了一个主机，故障后无法重路由连接串配置两个主机 + target_session_attrs=read-write；前端展示主节点状态与重连事件
MD5 不足以保护密码MD5 无盐、易碰撞，彩虹表可反查弱密码课程按 MD5 演示；文档明确生产改用 bcrypt/Argon2 + 盐 + HTTPS，并限制登录失败次数
CSV 中文乱码Excel 默认按本地编码打开无 BOM 的 UTF-8导出内容加 UTF-8 BOM；导入时去掉 BOM 并兼容 CRLF/LF
导入重复图书CSV 没有统一主键，重复导入产生副本按图书编号或“书名 + 作者”匹配，存在则更新、不存在则新增，并返回新增/更新/失败统计

4.3 小组合作的方法

小组按“数据库设计、后端接口、前端交互、测试与文档”四条线分工，但保持交叉评审，避免出现只有一个人理解全局的情况。建议在提交前把下表姓名替换为实际成员。

角色主要职责交付物
组长 / 数据库设计需求拆解、ER 图、关系模式、触发器与存储过程、主备方案schema.sql、设计文档第 2–3 章、答辩主讲
后端 / 高可用接口与鉴权、备份恢复流程、主备切换脚本、审计API 说明、备份/切换演示、问题清单
前端 / 交互读者门户、注册登录、读者评价、公告、控制台、SQL 实验台、导入导出页面与交互、演示脚本、截图/录屏
测试 / 文档用例与边界测试、数据准备、文档排版、演示彩排测试记录、演示账号、最终 PDF/视频
  • 协作节奏：每周一次 30 分钟站会同步进度与阻塞；需求变更先改文档再改代码；演示前至少完整彩排两次。
  • 版本管理：Git 分支按功能拆分（feature/borrow、feature/ha），提交信息写清“做了什么、为什么”；合并前互相 Review。
  • 接口契约：先确定表结构与接口字段，再并行开发；用固定演示数据（12 本书、7 个用户、22 条在借）保证每人环境一致。
  • 知识共享：数据库同学给前端讲触发器和事务，前端同学给数据库同学讲交互与错误提示；答辩前每人能独立完成整套演示。
  • 复盘：每次演示后记录卡顿点与老师提问，形成问题清单并在下一次迭代修复。

建议总时长 8–10 分钟，按“业务 → 数据库 → 高可用 → 运维”的顺序讲，避免一上来陷入代码细节。演示前先重置数据，保证库存与借阅数量一致。

时间画面操作与讲解要点

4.5 不足与改进

  • 当前为纯前端演示，数据库、主备与备份均为浏览器内模拟；生产版本需接入真实后端与 GaussDB，前端只保留接口调用。
  • MD5 仅满足课程要求，生产应改为 bcrypt/Argon2 + 盐，并增加登录限流、验证码与会话过期。
  • 主备切换演示未覆盖脑裂、双主、复制延迟过大等异常；生产需接入 DCS/etcd 仲裁与监控告警。
  • 评价与公告均为演示级实现；生产环境应增加敏感词审核、评价申诉与公告受众范围控制。
  • 权限校验目前由前端模拟，真实系统必须在后端接口逐项校验，并记录失败审计。
